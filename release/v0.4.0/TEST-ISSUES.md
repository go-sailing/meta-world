## ISSUE-001: LLM 不主动调用工具 - 直接瞎答

| 字段   | 内容                                                                                                               |
| ---- | ---------------------------------------------------------------------------------------------------------------- |
| 问题编号 | ISSUE-001                                                                                                        |
| 优先级  | P0                                                                                                               |
| 发现日期 | 2026-09-04                                                                                                       |
| 发现人  | QA 智能体                                                                                                           |
| 所属模块 | chat / tool-executor                                                                                             |
| 测试用例 | TC-002（直接问"现在几点了"）                                                                                               |
| 问题描述 | 用户自然语言提问"现在几点了"，LLM 直接瞎答时间，未调用 get\_time 工具                                                                      |
| 复现步骤 | 1. 用户发送 `{"message":"现在几点了"}` 2. 观察 tool\_steps 为空                                                               |
| 预期行为 | LLM 主动调用 get\_time 工具获取真实时间                                                                                      |
| 实际行为 | LLM 编造一个时间直接回答                                                                                                   |
| 根因分析 | 1. System prompt 中没有引导 LLM 积极使用工具 2. deepseek-v4-flash 对 function calling 的工具选择策略较保守                             |
| 解决方案 | **方案 A**：在 buildPrompt 的 system message 中增加工具使用引导**方案 B**：给 LLM 加 tool\_choice = "auto" + 在 user message 里追加工具提示 |
| 当前状态 | ✅ 已修复（2026-09-04）                                                                                                |
| 修复版本 | v0.4.0                                                                                                           |
| 修复说明 | 在 `buildPrompt` 的 system message 末尾增加了「工具使用指南」段落，引导 LLM 在涉及实时信息/文件操作/发信时必须调用工具。修复后自然语言"现在几点了"可正确触发 get\_time 调用。 |

## ISSUE-002: 工具 result 包装层数不一致

| 字段   | 内容                                                                                                                 |
| ---- | ------------------------------------------------------------------------------------------------------------------ |
| 问题编号 | ISSUE-002                                                                                                          |
| 优先级  | P1                                                                                                                 |
| 发现日期 | 2026-09-04                                                                                                         |
| 发现人  | QA 智能体                                                                                                             |
| 所属模块 | ToolRegistry                                                                                                       |
| 测试用例 | TC-003/004/005                                                                                                     |
| 问题描述 | 工具执行后返回的 result 被 ToolRegistry.execute 再包装一层，导致前端看到的结构是 `{ success:true, data: { success:true, ...} }` 双 success   |
| 复现步骤 | 1. 执行任意工具 2. 查看返回的 tool\_steps\[i].result                                                                          |
| 预期行为 | result 结构应该是 `{ success: bool, data: ... }` 或原始结果直接返回，不应有两层包装                                                      |
| 实际行为 | 如 file\_write 返回 `{ success: true, path, size }`，registry 又包一层变成 `{ success: true, data: { success: true, ... } }` |
| 根因分析 | 工具自己也返回了 `{ success: true }` 格式，registry.execute 又包了一层。应该统一为：工具返回原始数据，registry 负责标准化包装                             |
| 解决方案 | 修改所有内置工具的 execute 方法，去掉内部的 `{ success: true, ... }` 包装，直接返回原始数据                                                    |
| 当前状态 | ✅ 已修复（2026-09-04）                                                                                                  |
| 修复版本 | v0.4.0                                                                                                             |

## ISSUE-003: 前端 ToolCallCard 与流式消息时序 - 无空 assistant 消息时 tools 丢失

| 字段   | 内容                                                                                                                  |
| ---- | ------------------------------------------------------------------------------------------------------------------- |
| 问题编号 | ISSUE-003                                                                                                           |
| 优先级  | P1                                                                                                                  |
| 发现日期 | 2026-09-04                                                                                                          |
| 发现人  | QA 智能体                                                                                                              |
| 所属模块 | web/stores/chat.ts + web/api/chat.ts                                                                                |
| 问题描述 | 前端 chat API 收到 tools 事件时，如果 chatStore 里最后一条不是 assistant 消息，appendToolSteps 会自动创建空的 assistant 消息，但此时用户已经看到一个空气泡，体验不好 |
| 复现步骤 | 1. 用户发起对话前 chat.messages 为空 2. 后端先发 tools 再发 token 3. 前端先收到 tools，store 自动创建空 assistant 消息                          |
| 预期行为 | tools 和后续的 token 应合并到同一个 assistant 气泡中                                                                              |
| 实际行为 | 可能出现空气泡 + 后续 token 气泡分离的情况                                                                                          |
| 根因分析 | 时序竞争：tools 事件到达时 assistant 消息还未被 push                                                                               |
| 解决方案 | 在 Chat.vue 的 send() 里先推一个空 assistant 消息，确保 tools 到达时有挂载点。当前实现已这么做了，但流式场景仍需验证                                        |
| 当前状态 | ✅ 已修复（2026-09-04）                                                                                                   |
| 修复版本 | v0.4.0                                                                                                              |

## ISSUE-004: send\_letter 工具与通讯录校验 - 缺少友好错误提示

| 字段   | 内容                                                                          |
| ---- | --------------------------------------------------------------------------- |
| 问题编号 | ISSUE-004                                                                   |
| 优先级  | P2                                                                          |
| 发现日期 | 2026-09-04                                                                  |
| 发现人  | QA 智能体                                                                      |
| 所属模块 | tools/builtins/send-letter.ts                                               |
| 问题描述 | 发送信件时目标不在通讯录，返回 `error: "NOT_IN_ADDRESS_BOOK"` 英文错误码，LLM 可能不会翻译成中文告知用户      |
| 复现步骤 | 让智能体给一个不在通讯录的目标发信                                                           |

| 根因分析 | 工具层统一返回英文 error code，LLM 负责翻译，但 LLM 不一定能准确翻译 code                           |
| 解决方案 | 在 send\_letter 工具的错误返回中增加中文 detail 字段，或让 LLM 在 system prompt 中知道这些 code 的含义 |
| 当前状态 | ✅ 已修复（2026-09-04）                                                           |
| 修复版本 | v0.4.0                                                                      |
