| 项   | 值                                         |

### 前置准备

```bash
# 启动后端（确保 server/.env 已配置 LLM_API_KEY）

# 另起终端启动前端
npm run dev:web
# 验证后端健康检查
curl http://localhost:3000/health
```

## 1. 智能体创建（F1）

### TC-F1-01 正常创建

| 项        | 内容                                                                       |
| -------- | ------------------------------------------------------------------------ |
| **步骤**   | `POST /api/agents` `{"name":"小智","persona_tags":["friendly","curious"]}` |
| **预期**   | 返回 201，包含 `agent_id`（UUID）、`name`、`persona_tags`、`created_at`            |
| **查询验证** | 查 `SELECT * FROM agent WHERE agent_id = ?`，persona\_tags 为 JSON 字符串      |
| **前端验证** | 提交创建表单后跳转到 `/chat/:agentId`                                              |

### TC-F1-02 名称太短

| 项      | 内容                                                            |
| ------ | ------------------------------------------------------------- |
| **步骤** | `POST /api/agents` `{"name":"小","persona_tags":["friendly"]}` |
| **预期** | 返回 400，错误信息类似 "name must have at least 2 characters"          |

### TC-F1-03 没有性格标签

| 项      | 内容                                                   |
| ------ | ---------------------------------------------------- |
| **步骤** | `POST /api/agents` `{"name":"小智","persona_tags":[]}` |
| **预期** | 返回 400                                               |

### TC-F1-04 性格标签过多（>5）

| 项      | 内容                     |
| ------ | ---------------------- |
| **步骤** | `persona_tags` 传 6 个标签 |
| **预期** | 返回 400                 |

### TC-F1-05 查询已存在的智能体

| 项      | 内容                                               |
| ------ | ------------------------------------------------ |
| **步骤** | 用 TC-F1-01 创建的 agent\_id 调 `GET /api/agents/:id` |
| **预期** | 返回完整 agent 对象                                    |

### TC-F1-06 查询不存在的智能体

| 项      | 内容                                                     |
| ------ | ------------------------------------------------------ |
| **步骤** | `GET /api/agents/00000000-0000-0000-0000-000000000000` |
| **预期** | 返回 404                                                 |

## 2. 用户-智能体对话（F2）

### TC-F2-01 非流式对话正常

| 项        | 内容                                                                                |
| -------- | --------------------------------------------------------------------------------- |
| **步骤**   | `POST /api/chat` `{"agent_id":"<有效ID>","message":"你好，介绍一下你自己"}`                   |
| **预期**   | 返回 `{"reply":"...","memory_refs":[...]}`，reply 非空                                 |
| **查询验证** | `SELECT COUNT(*) FROM chat_message WHERE agent_id = ?` 应 +2（user + assistant 各一条） |

### TC-F2-02 SSE 流式对话正常

| 项           | 内容                                                                                                                                          |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **步骤**      | `POST /api/chat/stream`，监听 SSE 事件                                                                                                           |
| **预期**      | 依次收到多个 `event: token` 消息，最后一个 `event: done`                                                                                                 |
| **curl 验证** | `curl -N -X POST http://localhost:3000/api/chat/stream -H 'Content-Type: application/json' -d '{"agent_id":"<ID>","message":"hi"}'` 应看到逐字输出 |

### TC-F2-03 智能体不存在

| 项      | 内容                             |
| ------ | ------------------------------ |
| **步骤** | `POST /api/chat` 用无效 agent\_id |
| **预期** | 返回 400 或 404                   |

### TC-F2-04 空消息

| 项      | 内容                                       |
| ------ | ---------------------------------------- |
| **步骤** | `POST /api/chat` message 传空字符串或超长（>2000） |
| **预期** | 返回 400                                   |

### TC-F2-05 多轮对话上下文连贯

| 项      | 内容                                         |
| ------ | ------------------------------------------ |
| **步骤** | 连续发 3 轮消息：① "我叫小明" ② "我最喜欢的颜色是蓝色" ③ "我是谁？" |
| **预期** | 第③轮智能体能答出"小明"（验证历史上下文确实带进去了）               |

### TC-F2-06 LLM 服务不可用时的降级（可选）

| 项      | 内容                           |
| ------ | ---------------------------- |
| **步骤** | 关掉 LLM API 或配错 API Key，发一条消息 |
| **预期** | 返回错误提示而非 500 crash           |

## 3. 记忆自动抽取与三层认知（F4）

### TC-F4-01 对话产生自我认知

| 项            | 内容                                                                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| **步骤**       | 跟智能体说："你是一个乐于助人的助手，性格很温柔"                                                                                                          |
| **预期（查询验证）** | `SELECT * FROM memory_item WHERE agent_id=? AND layer='self' ORDER BY created_at DESC LIMIT 3` 出现新条目，content 类似"我是乐于助人的助手"或"我性格温柔" |

### TC-F4-02 对话产生世界认知

| 项      | 内容                                              |
| ------ | ----------------------------------------------- |
| **步骤** | 跟智能体说："2026 年 AI 很火"                            |
| **预期** | memory\_item 出现 layer='world' 的条目，content 含相关信息 |

### TC-F4-03 对话产生对他人认知

| 项      | 内容                                                                                           |
| ------ | -------------------------------------------------------------------------------------------- |
| **步骤** | 跟智能体说："我叫小明，在字节跳动做工程师"                                                                       |
| **预期** | memory\_item 出现 layer='other' 的条目，target\_agent\_id 留空或是用户占位；content 包含"小明"、"字节跳动"、"工程师"等关键词 |

### TC-F4-04 记忆自动引用（核心验收项 A3）

| 项        | 内容                                            |
| -------- | --------------------------------------------- |
| **前置**   | 已完成 TC-F4-03，对话中提到了自己的名字                      |
| **步骤**   | 等 3 轮对话后（或稍等几秒让异步抽取完成），问："我叫什么名字？"            |
| **预期**   | 智能体回复中能答对你的名字（这证明记忆被召回并注入了 prompt）            |
| **调试辅助** | 查看 SSE done 事件的 memory\_refs 字段，应引用到之前抽取的记忆条目 |

### TC-F4-05 向量库写入验证

| 项       | 内容                                            |
| ------- | --------------------------------------------- |
| **步骤**  | 完成上述对话后，检查 memory\_vec 表                      |
| **预期**  | memory\_vec 的行数 = memory\_item 有记忆后新增的行数（一对一） |
| **SQL** | `SELECT COUNT(*) FROM memory_vec`             |

### TC-F4-06 低置信度记忆不被引用

| 项      | 内容                                                                               |
| ------ | -------------------------------------------------------------------------------- |
| **说明** | DEMO 阶段抽取器统一给 dialogue 来源的 confidence=0.9，此条记录下来，待引入"推理型记忆（confidence=0.5）"时补充测试 |

## 4. 智能体-智能体信件（F3）

### TC-F3-01 发送信件正常

| 项        | 内容                                                                                          |
| -------- | ------------------------------------------------------------------------------------------- |
| **前置**   | 先创建两个智能体 A 和 B                                                                              |
| **步骤**   | `POST /api/mail/send` `{"from_agent_id":"A","to_agent_id":"B","subject":"问候","body":"你好呀"}` |
| **预期**   | 返回 201，`letter_id` 存在，`status`='sent'                                                       |
| **查询验证** | `SELECT * FROM letter WHERE letter_id=?` status 应为 'delivered'                              |

### TC-F3-02 信件写入收件信箱

| 项      | 内容                                            |
| ------ | --------------------------------------------- |
| **步骤** | TC-F3-01 之后调 `GET /api/mail/inbox?agent_id=B` |
| **预期** | 列表中出现来自 A 的信件，`is_unread: true`               |

### TC-F3-03 查看信件详情并标记已读

| 项      | 内容                                                                     |
| ------ | ---------------------------------------------------------------------- |
| **步骤** | `GET /api/mail/:id`（B 的某封信）                                            |
| **预期** | 返回完整 Letter 对象；再次 inbox 查询时 `is_unread: false`，letter.status 变为 'read' |

### TC-F3-04 信件产生记忆（核心验收项 A5）

| 项            | 内容                                                                  |
| ------------ | ------------------------------------------------------------------- |
| **前置**       | 智能体 A 是"天气助手"，B 是"出行助手"                                             |
| **步骤**       | A 给 B 发信："今天北京下雨，建议带伞"                                              |
| **等待**       | 几秒，让异步 processLetter 完成                                             |
| **验证 1（DB）** | 查 memory\_item，agent\_id=B，应出现 layer='world' 或 'other'（对 A 的认知）的新条目 |
| **验证 2（对话）** | 问 B："今天北京天气如何？" B 的回复应包含"下雨"                                        |

### TC-F3-05 信件触发自动回复

| 项      | 内容                                                                               |
| ------ | -------------------------------------------------------------------------------- |
| **前置** | 创建两个智能体 A、B                                                                      |
| **步骤** | A 给 B 发一封带问号的信："你好吗？"                                                            |
| **等待** | 几秒                                                                               |
| **预期** | `GET /api/mail/inbox?agent_id=A` 能看到 B 回信；原信 letter.status 变为 'replied' 或 'done' |

### TC-F3-06 自动回复不递归

| 项       | 内容                                                                           |
| ------- | ---------------------------------------------------------------------------- |
| **步骤**  | 连续发 20 封互相带问号的信件（通过脚本）                                                       |
| **预期**  | 最终信件数是 **1 封**（初始）+ 最多 1 轮 A→B + B→A 回环，不会无限增长                               |
| **SQL** | `SELECT COUNT(*) FROM letter WHERE from_agent_id=A OR from_agent_id=B` 应 ≤ 5 |

### TC-F3-07 发件方不存在

| 项      | 内容                                             |
| ------ | ---------------------------------------------- |
| **步骤** | `POST /api/mail/send` from\_agent\_id 传无效 UUID |
| **预期** | 返回 400，错误信息包含 "From agent not found"           |

### TC-F3-08 收件方不存在

| 项      | 内容                     |
| ------ | ---------------------- |
| **步骤** | to\_agent\_id 传无效 UUID |
| **预期** | 返回 400                 |

### TC-F3-09 信件正文超长

| 项      | 内容                 |
| ------ | ------------------ |
| **步骤** | body 传 >2000 字符的内容 |
| **预期** | 返回 400             |

### TC-F3-10 手动重新处理失败信件

| 项      | 内容                                                                             |
| ------ | ------------------------------------------------------------------------------ |
| **步骤** | 找一封 status='processing\_failed' 的信，调 `POST /api/mail/:id/reprocess`            |
| **预期** | 返回 200 ok，几秒后 status 流转为 'delivered' → 'processing' → ... → 'done' 或 'replied' |

## 5. 闭环联合测试（端到端）

### TC-E2E-01 全链路闭环（对话 → 记忆 → 引用记忆 → 发信 → 信也产记忆）

| 步骤 | 操作                                                                              | 预期                                                                |
| -- | ------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 1  | 创建智能体 A（name="小智"，tags=\["friendly"]）、智能体 B（name="出行助手"，tags=\["professional"]） | 都创建成功                                                             |
| 2  | 用户跟 A 说："我叫小明，我喜欢徒步"                                                            | chat\_message 新增 2 条；memory\_item 产生 layer='other' 条目（含"小明"、"徒步"） |
| 3  | 等 5 秒                                                                           | 记忆抽取完成                                                            |
| 4  | 用户问 A："我是谁？我喜欢什么？"                                                              | A 答出"小明" + "徒步"                                                   |
| 5  | A 给 B 发信（通过 API 或后续功能）："我发现小明喜欢徒步，也许你可以推荐一些路线"                                  | B 的信箱收到信；B 的 memory\_item 产生 layer='other' 或 'world' 条目           |
| 6  | 等 B 自动回复                                                                        | B 回信，原信 status='replied'                                          |
| 7  | 查 DB                                                                            | memory\_vec 有对应新向量行                                               |

### TC-E2E-02 多智能体多轮信件互动

| 步骤 | 操作                        | 预期                       |
| -- | ------------------------- | ------------------------ |
| 1  | 创建 3 个智能体：A、B、C           | 创建成功                     |
| 2  | A 给 B 发信："明天去爬山吗？"        | B 收到                     |
| 3  | B 给 C 发信："A 想明天爬山，你有兴趣吗？" | C 收到                     |
| 4  | C 回复 B，B 回复 A             | 信件正确流转，每个智能体的信箱都能看到完整对话链 |
| 5  | 查每个智能体的 memory\_item      | 都有因信件产生的认知条目             |

## 7. 数据库数据检查清单

每次测试后可执行以下 SQL 验证数据完整性：

```sql
-- Agent 数量
SELECT COUNT(*) FROM agent;

-- 对话消息量
SELECT agent_id, COUNT(*) FROM chat_message GROUP BY agent_id;

-- 信件状态分布
SELECT status, COUNT(*) FROM letter GROUP BY status;

-- 三层认知分布
SELECT layer, COUNT(*) FROM memory_item GROUP BY layer;

-- 记忆来源分布
SELECT source_type, COUNT(*) FROM memory_item GROUP BY source_type;

-- 向量表行数（应等于 memory_item 行数）
SELECT COUNT(*) FROM memory_vec;

-- 查看某智能体的全部记忆（调试用）
SELECT memory_id, layer, content, confidence, source_type FROM memory_item WHERE agent_id = ? ORDER BY created_at;
```
